## 1. 为什么用 KuaiRand 作为“推荐 → 因果推断”的第一块跳板？

如果你熟悉传统推荐系统（精排 CTR/完播率、双塔召回、DIN 序列建模，以及像 **MiniOneRec** 这样的生成式推荐），你在做离线训练和评估时，默认面对的都是**线上推荐策略已经筛选过的日志**：

- 线上精排模型倾向于把**热门视频**、**历史点击率高的视频**推给用户；
- 用户只能对自己**“被曝光”**的视频产生点击/点赞/完播行为，没曝光的视频我们根本不知道用户喜不喜欢；
- 这导致常规推荐日志天生存在严重的 **Exposure Bias（曝光偏差） / Selection Bias（选择偏差）**——数据不是 **MAR（Missing At Random，随机缺失）**，而是 **MNAR（Missing Not At Random，非随机缺失）**。

**KuaiRand 的核心价值**在于：它直接来自快手真实业务，不仅记录了常规推荐系统的海量曝光日志，还在真实线上流量中做了一次大规模的**随机插播干预实验（Random Exposure Intervention）**——把一批候选视频以等概率随机插入用户的推荐信息流中，从而拿到了宝贵的**无偏（Unbiased / MAR）用户反馈**。

> **和你在「增长策略 / 激励效率」组工作的第一层直觉映射**：
> - 推荐系统问的是：“给这个用户推这个视频，他会喜欢吗？”——但历史日志里只推了模型觉得好的视频。
> - 激励效率组问的是：“给这个用户发 5 毛钱激励/红包，他会多留存或产生增量转化吗？”——但历史策略往往只给特定人群发激励。
> - **共同痛点**：只要干预动作（推哪个视频 / 给谁发激励）不是随机分配的，直接拿历史日志做预测或算均值，都会被**选择偏差**误导。KuaiRand 里的“随机曝光流量”，本质上就是推荐场景里的 **RCT（随机对照实验）**。

## 2. 三个版本定位与选型建议

KuaiRand 官方提供了三个子集版本，核心差异在于**用户规模、候选视频范围和磁盘体积**：

| 版本 | 用户数 | 视频数 | 交互日志规模 | 磁盘体积（约） | 核心定位与适用场景 |
| :--- | :---: | :---: | :---: | :---: | :--- |
| **KuaiRand-27K**（完整版） | 27,285 | 32,038,725 | 标准日志 ~3.22 亿<br>随机日志 1,186,059 | 日志 ~23GB<br>特征 ~23GB | 超大规模长序列建模、多任务学习、工业级离线仿真 |
| **KuaiRand-1K**（中型版） | 1,000（随机抽样） | 仅保留相关视频 | 1,000 用户的完整序列与随机日志 | 日志 ~829MB<br>特征 ~3.5GB | 算力受限时的序列推荐、强化学习（RL）、OPE 实验 |
| **KuaiRand-Pure**（轻量版，**推荐首选**） | 27,285 | **7,583**（仅保留随机候选池视频） | 标准日志 **1,436,609**<br>随机日志 **1,186,059** | 日志 ~184MB<br>特征 ~10MB | **纠偏（Debiasing）、反事实学习、离线无偏评估（OPE）** |

### 为什么我们动手实验优先选 `KuaiRand-Pure`？
1. **体积友好**：总计不到 200MB，在普通开发机或笔记本上几秒钟就能加载进 `pandas` 跑完实验。
2. **Item 空间完全对齐**：`KuaiRand-Pure` 只保留了那 **7,583 个参与随机插播的候选视频**。这意味着同一批视频，既有**常规推荐策略**推出来的有偏日志（143.6 万条），又有**随机策略**推出来的无偏日志（118.6 万条）——**这是对比“有偏分布 vs 无偏分布”和验证 IPS / DR 纠偏效果最干净的实验沙箱**。

## 3. 快手业务侧“随机插播曝光”采集机制

理解数据的**生成机制（Data Generating Process, DGP）**是因果推断的第一步。KuaiRand 的采集分为两个连续时间段（2022 年 4 月—5 月）：

```text
[阶段 A：2022-04-08 ~ 2022-04-21（前两周）]
  └── 纯常规推荐日志（log_standard_4_08_to_4_21）
      作用：提供用户的历史行为序列，用于建模用户长期兴趣 / 作为前置协变量 X

[阶段 B：2022-04-22 ~ 2022-05-08（后两周多）]
  ├── 常规推荐日志（log_standard_4_22_to_5_08）：线上 15 个推荐场景/策略（tab 0~14）的正常曝光
  └── 随机干预日志（log_random_4_22_to_5_08）：从 7,583 个候选视频池中【均匀随机采样】，
      直接替换插入到正常推荐流中（标记 is_rand = 1）
```

### 采集设计中的 3 个关键工程细节（因果视角必看）
1. **候选池抽样与覆盖度**：这 7,583 个视频构成固定的随机曝光候选池，每个视频都有均等概率被抽中插入推荐流，且在实验结束时所有 7,583 个视频都至少被随机插入曝光过 1 次。
2. **用户过滤门槛**：最终保留的 27,285 名活跃用户，都满足**至少被曝光过 10 次随机插播视频**，从而保证在用户粒度上也能做相对稳健的无偏评估。
3. **为什么要区分 `standard` 和 `random` 的时间窗口？**
   - 如果拿 `4_08 ~ 4_21`（甚至 `4_22 ~ 5_08` 的 `standard`）做训练集，拿 `4_22 ~ 5_08` 的 `random` 做测试集，你就能清晰检验：**一个在有偏训练集上 AUC 很高的推荐模型，放到无偏随机流量上表现到底怎么样？**

## 4. 核心表结构与字段拆解

以 `KuaiRand-Pure` 为例，数据主要分为**交互日志表**和**侧信息特征表**两大类：

### 4.1 交互日志表（`log_standard_*.csv` & `log_random_*.csv`）

| 字段分组 | 核心列名 | 含义与因果/业务解读 |
| :--- | :--- | :--- |
| **主键与上下文** | `user_id`, `video_id`, `date`, `hourmin`, `time_ms` | 用户 ID、视频 ID、曝光日期与毫秒级时间戳（可用于构建序列特征或按时间切分，防止时间穿越） |
| **干预与场景标记** | **`is_rand`** | **最核心的因果标记**：`1` 表示由随机插播策略曝光（MAR 无偏），`0` 表示由常规推荐策略曝光（MNAR 有偏） |
| | **`tab`** | 曝光所在的 App 场景/页面（`0`–`14` 共 15 种场景，例如主发现页、精选单列流等，对应不同业务策略与页面交互形态） |
| **视频基础时长** | `duration_ms` | 视频本身的总时长（毫秒），用于和 `play_time_ms` 结合计算完播率 / 相对观看比例 |
| **核心反馈信号（12 维丰富信号）** | `is_click` | 是否有效点击/播放（双列流为点击，单列流按观看时长阈值定义为有效播放） |
| | `long_view` | 是否长观（观看时长达到较高比例，强隐式正向信号） |
| | `play_time_ms` | 实际观看时长（毫秒，连续型核心消费指标） |
| | `is_like`, `is_follow`, `is_comment`, `is_forward` | 显式正向互动：点赞、关注作者、评论、转发 |
| | `is_hate` | **显式负反馈**（点击“不感兴趣/讨厌”，在推荐和增长中都极其重要，对应负向体验成本） |
| | `is_profile_enter`, `profile_stay_time`, `comment_stay_time` | 深度探索信号：是否进入作者主页、主页停留时长、评论区停留时长 |

> **给熟悉多目标推荐（MMoE/PLE）的你的提示**：
> 传统纠偏数据集（如 Yahoo! R3、Coat）往往只有单一的评分或点击信号；而 KuaiRand 同时给了 12 维反馈信号（短期点击 + 深度时长 + 显式互动 + 负反馈）。这在激励效率业务里也非常有启发——发激励可能拉高了短期点击/打卡（短期代理指标），但会不会引发 `is_hate` 类的打扰负反馈或拉低长期留存？

### 4.2 侧信息特征表（Side Information）

在因果推断里，这些静态/统计特征就是用来控制混杂因子的**协变量（Covariates, $X$）**：

1. **`user_features.csv`（约 30 维用户特征）**
   - 包含用户活跃度分层（如 `user_active_degree`）、注册天数、关注数/粉丝数/好友数、是否低活/实名，以及脱敏后的类别特征（`onehot_feat0` ~ `onehot_feat17`）。
   - **因果意义**：高活用户本身就更容易点击和完播，同时也更容易被线上策略选中——这就是最典型的 **Confounder（混杂因子）**。
2. **`video_features_basic.csv`（视频基础属性）**
   - 包含 `video_id`、`author_id`、`video_type`（普通视频 `NORMAL` / 广告 `AD`）、上传日期 `upload_dt`、视频时长、音乐 ID、标签 `tag` 等。
3. **`video_features_statistic.csv`（视频统计特征，与 basic 合计约 62 维）**
   - 包含视频的历史累计曝光量、播放量、点赞/评论/关注数等统计量。
   - **实战预警（Data Leakage / 后果变量陷阱）**：统计特征里如果包含了曝光后的累计互动数，在因果建模中要格外小心**目标穿越（Leakage）**或**对撞偏倚（Collider Bias）**——这一点我们会在 Phase 2 和 Phase 4 详细展开。

## 6. 本阶段思考题（检验直觉）

在进入 **Phase 2（从推荐到因果推断再到激励效率的概念桥接）** 之前，可以先带着这两个贴近业务的小问题思考 1 分钟：

1. **为什么不能全量随机？** 既然随机曝光（`is_rand=1`）的数据是无偏的，为什么快手线上不能直接把 100% 流量都改成随机曝光，而只能小流量抽样插入？这对应到你们**激励效率组**做随机对照实验（比如随机抽一部分用户发券/不发券）时，面临的同样是什么约束？
2. **指标方向直觉预测**：在 `KuaiRand-Pure` 里，同一批 7,583 个视频，你直觉上认为 **`log_standard`（常规推荐流量）的平均点击率 `is_click` 会比 `log_random`（随机插播流量）高很多，还是差不多？** 如果我们直接拿 `log_standard` 训练一个普通 CTR 模型，它对“冷门但优质”的视频会犯什么错误？
